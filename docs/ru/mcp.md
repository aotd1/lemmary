# MCP для агентов {#mcp-for-agents}

Lemmary может отдавать свой архив по [Model Context Protocol](https://modelcontextprotocol.io), чтобы агент — Claude Code, Claude Desktop, Cursor или написанный вами — искал и читал ваши документы напрямую, а не через браузер. Эндпоинт доступен только для чтения, пока администратор не разрешит изменения, и использует тот же поиск, что и Deep Search: токен видит ровно то, что его пользователь видит в приложении, и ничего больше.

## Включено по умолчанию {#it-is-on-by-default}

Эндпоинт отвечает только на bearer-токен и ничего не стоит, пока его не вызовет агент, поэтому он включён, если оператор его не отключит:

```env
MCP_ENABLED=0
```

В отключённом состоянии маршрута нет вовсе. После изменения перезапустите приложение: флаг читается один раз при запуске.

## Получение токена {#get-a-token}

На странице учётной записи есть раздел **Агенты**: одним нажатием создаётся долгоживущий токен для вашей учётной записи и показывается готовая к вставке конфигурация для Claude Code, Codex CLI, Gemini CLI, Cursor, VS Code, Windsurf, OpenCode и Claude Desktop (в виде команды, если у агента она есть, иначе — в виде его конфигурационного файла).

Подойдёт и любой токен аутентификации Lemmary. Из скрипта удобнее всего взять долгоживущий токен из эндпоинта, совместимого с paperless:

```bash
TOKEN=$(curl -s -X POST https://lemmary.example.com/api/token/ \
  -d username=you@example.com -d password=… | jq -r .token)
```

Каждый токен ограничен документами одной учётной записи. Токен администратора соответствует собственной учётной записи администратора в `users` (той, что создаётся вместе с ним при настройке), а не всем учётным записям экземпляра.

Токен действует десять лет, и создание нового не отменяет прежние. Смена пароля в разделе **Учётная запись → Пароль** отзывает сразу все токены, включая токены приложений Paperless-ngx; отозвать один отдельно нельзя.

## Подключение {#connect}

Сервер работает по Streamable HTTP на `POST /api/mcp` и ожидает `Authorization: Bearer <token>`. Как требует протокол, запросы передают `Accept: application/json, text/event-stream`; MCP-клиенты делают это сами, а в самодельном `curl` это нужно указать вручную.

Claude Code:

```bash
claude mcp add --transport http lemmary https://lemmary.example.com/api/mcp \
  --header "Authorization: Bearer $TOKEN"
```

Claude Desktop, Cursor и большинство других клиентов принимают то же самое в виде JSON:

```json
{
  "mcpServers": {
    "lemmary": {
      "type": "http",
      "url": "https://lemmary.example.com/api/mcp",
      "headers": { "Authorization": "Bearer …" }
    }
  }
}
```

## Инструменты {#tools}

Два вида: поиск по индексу и простой доступ к записям. Интеллект находится в вашем агенте, поэтому ничто здесь не вызывает языковую модель.

| Инструмент | Что делает |
| --- | --- |
| `search_documents` | Гибридный поиск по смыслу и ключевым словам в полнотекстовом и векторном индексе с необязательными фильтрами по дате, типу, корреспонденту и тегам. Возвращает подходящие документы, у каждого — от одного до трёх дословных фрагментов. |
| `read_documents` | Части до десяти документов, важные для заданного `focus`, ранжированные тем же индексом. Длинные документы возвращаются фрагментами с отмеченными пропусками. |
| `list_documents` | Простой список по метаданным: диапазон дат, тип документа, корреспондент, теги, статус обработки (`unfinished` означает всё, кроме завершённых); сортировка по дате или по времени добавления; постраничный вывод через `limit` и `offset`. Возвращает метаданные и общее количество, без текста. |
| `get_document` | Метаданные одного документа и его извлечённый текст, без ранжирования и сокращений. Один вызов возвращает до 200 000 символов; более длинный текст листайте через `offset` и `max_chars`, а `truncated` сообщает, что есть продолжение. |
| `count_documents` | Подсчёт документов, подходящих под фильтры, с необязательной группировкой по `document_type`, `correspondent`, `year`, `month` или `tag`. |
| `list_taxonomy` | Названия тегов, типов документов и корреспондентов в архиве для перечисленных выше фильтров. Каждый список обрывается на 5000 названиях и сообщает об этом через `truncated`. |

## Ссылки на файлы {#file-links}

При `MCP_FILE_LINKS_ENABLED=1` ответ `get_document` также содержит `original_file` и, если есть превью, `preview`: оригинал и PNG его первой страницы. В каждом блоке есть `url`, `filename`, `mime_type`, `size_bytes` и `expires_at`. Байты файлов и base64 в ответ инструмента не входят. `include_text: false` убирает OCR-текст; `text_chars` по-прежнему сообщает его полную длину. По умолчанию текст возвращается как раньше.

Укажите в существующей настройке PocketBase **Application URL** (`meta.appURL`) публичный базовый адрес, доступный агентам и пользователям, например `https://lemmary.example.com`, включая префикс пути, если он есть. Ссылки используют эту настройку, а не Host MCP-запроса или заголовки переадресации: вызов через внутренний gateway тоже возвращает публичные URL. Изменение настройки действует со следующего `get_document` без перезапуска. Отдельной переменной окружения для публичного адреса MCP нет.

Ссылка действует три минуты и не требует заголовка авторизации: любой её обладатель может скачать только этот файл. Она не позволяет авторизоваться в аккаунте, скачать другой документ или переключиться между оригиналом и превью. При скачивании доступ проверяется заново; удаление общего доступа, удаление/замена файла или смена ключа токенов аккаунта делает ссылку недействительной. Ответы не кэшируются. Считайте URL временными чувствительными данными, не журналируйте и не публикуйте его. Для обновления истёкшей ссылки повторите `get_document`.

Агент может скачать ссылку прямо в локальный файл и отправить его вложением без передачи байтов через модель. Рассматривание изображения визуальной моделью — отдельное действие, которое занимает визуальный контекст. Если превью не создано (в том числе для загруженных изображений), его ссылка отсутствует; для изображения используйте оригинал. Ссылки на файлы по умолчанию выключены, выключение убирает и маршрут скачивания. Дополнительных MCP-инструментов и расходов на AI нет.

## Инструменты записи {#write-tools}

Изменение архива по умолчанию выключено. Администратор включает каждый вид изменений в **Настройки → MCP** — сразу для токенов всех пользователей; выключенный инструмент вообще не предлагается. Любая запись затрагивает только документы и теги, принадлежащие пользователю токена: документ, которым с ним поделились, остаётся доступным только для чтения.

| Переключатель | Инструменты | Что делает |
| --- | --- | --- |
| Редактировать метаданные | `update_document` | Задаёт документу название, краткое содержание, дату, тип документа, корреспондента (оба создаются по имени, если их нет) и теги (существующие имена, весь список) и завершает проверку. Правка считается сделанной вручную. |
| Повторно обрабатывать документы | `reprocess_documents` | Заново ставит до 50 документов в очередь на OCR и извлечение (`auto`, `full` или `extraction`). Расходует ИИ, а извлечение перезаписывает метаданные, включая ручные правки. |
| Загружать документы | `upload_document` | Добавляет один файл в base64, до 32 МБ; действуют те же типы, лимиты и проверка дубликатов, что и на странице загрузки, и файл обрабатывается как любой другой. |
| Удалять документы | `delete_documents` | Удаляет до 50 документов вместе с файлами. Безвозвратно: корзины нет. |
| Управлять тегами | `create_tag`, `rename_tag`, `delete_tag` | Создаёт, переименовывает и удаляет теги по имени. Удалённый тег снимается с документов, сами документы остаются. |

Переключатель действует со следующего вызова, без перезапуска. Для существующих клиентов писать по-прежнему можно через [API paperless-ngx](/ru/paperless_ngx).

## Во что это обходится {#what-it-costs}

Каждый вызов `search_documents` — это один поиск Deep Search: полнотекстовый запрос и, если настроены эмбеддинги, один запрос эмбеддинга к вашему провайдеру для текста запроса. Вызов `read_documents` с `focus` точно так же получает эмбеддинг для focus. Ничто здесь не вызывает языковую модель, поэтому токены чата не расходуются. Агент, работающий в цикле, всё равно платит за каждый вызов — с вашего ключа. Повторная обработка и загрузка проходят конвейер обработки на тех же моделях и за тот же счёт, что и любой другой документ. Пока флаг не задан, ничего не расходуется.
